# FightCar 格斗小车

基于鲁班猫 Ubuntu 开发板的四轮格斗小车项目。目前围绕底盘运动控制展开，支持通过 SSH 终端键盘或 Windows 上位机操作小车，用于行驶、转向和运动参数调试。

## 小车组成

| 部分 | 说明 |
|---|---|
| 主控 | 鲁班猫开发板，运行 Ubuntu 和 Python 控制程序 |
| 底盘 | 四个电机，左右两侧各两个电机 |
| 驱动 | 两个驱动器，每个负责一侧电机；软件默认左侧 ID 1、右侧 ID 2 |
| 操作端 | Windows 电脑，通过 SSH 终端或图形上位机控制 |
| 硬件接口 | 板端厂商库 `libuptech.so` 及 Python 接口 |

小车通过左右两侧的速度差实现转向。当前采用开环控制，没有接入轮速反馈；程序中的速度是驱动控制值，不能直接当作 RPM。电机完整型号和驱动器实物型号仍待确认，参考资料中的驱动器说明为 BDMC1203。

## 控制功能

目前程序提供以下功能：

- 前进、后退和停车。
- 原地向左、向右旋转，旋转速度可独立设置。
- 按设定半径向前转弯，可调整轮距和转弯半径。
- 运行中调整行驶速度、旋转速度和转弯参数。
- 松键超时、换向、断线和程序退出时请求停车。
- 在电脑上使用模拟模式体验上位机操作。

转弯半径由左右轮控制值估算，实际轨迹会受轮距、地面摩擦和电机差异影响。

## 使用前准备

实车控制需要开发板已安装配套厂商库，并能通过 SSH 登录。连接参数保存在 [config/board.json](config/board.json)，当前为 `bcsh@192.168.3.88`，板端代码目录为 `~/hsy/ceshi`。

以下实车命令按板端四个脚本已放入该目录编写；若复制的是整个项目，请先进入项目的 `src/board/`。首次测试应架空车轮，键盘控制、上位机服务和单路电机测试每次只运行一个。

## 方式一：SSH 键盘控制

在 Windows 终端连接开发板：

```powershell
ssh bcsh@192.168.3.88
```

进入板端程序目录并启动：

```bash
cd ~/hsy/ceshi
sudo python3 keyboard_car.py --speed 300 --spin-speed 200
```

按住动作键控制小车，按键含义如下：

| 按键 | 功能 |
|---|---|
| W / S 或 ↑ / ↓ | 前进 / 后退 |
| A / D 或 ← / → | 原地左旋 / 右旋 |
| J / L | 按设定半径向前左转 / 右转 |
| 空格 | 停车 |
| + / - | 增大 / 减小行驶速度 |
| R / F | 增大 / 减小旋转速度 |
| [ / ] | 减小 / 增大转弯半径 |
| Q 或 Ctrl+C | 退出并尝试停车 |

终端模式约 0.6 秒没有收到动作按键后请求停车。行驶和旋转速度范围均为 1～1023；默认轮距 0.30 m、半径 0.50 m 为示例值，使用时应按实际小车调整。

## 方式二：Windows 上位机控制

1. 在 Windows 终端建立 SSH 隧道：

   ```powershell
   ssh -L 8765:127.0.0.1:8765 bcsh@192.168.3.88
   ```

2. 在该 SSH 终端中启动板端服务，保持终端打开：

   ```bash
   cd ~/hsy/ceshi
   sudo python3 motor_server.py
   ```

3. 在 Windows 另一个终端进入项目根目录，启动上位机：

   ```powershell
   py -3 src/desktop/windows_client.py
   ```

也可双击 `src/desktop/启动上位机.cmd`。在窗口中连接 `127.0.0.1:8765`，即可操作方向按钮，实时设置行驶速度、旋转速度、轮距和半径。上位机通过 SSH 隧道发送指令，由开发板计算左右轮控制值并调用电机接口。

## 电脑模拟

在项目根目录打开两个 Windows 终端，分别运行：

```powershell
py -3 src/board/motor_server.py --simulate
```

```powershell
py -3 src/desktop/windows_client.py
```

上位机连接 `127.0.0.1:8765`，可检查操作界面和指令通信。模拟模式不加载电机库，也不控制真实电机。

## 当前进展

实车已反馈前进、后退正常。原地旋转曾出现仅一侧转动的情况，近似原地转弯对照后反馈两侧可转动，但 A/D 是否完全恢复、左右速度差异及故障根因仍待进一步验证。

当前重点是底盘控制与调试。老师提供的视觉识别、传感器和比赛策略示例保存在 `reference/`，尚未整合为本车的自动格斗功能。
